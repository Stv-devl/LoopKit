# A11y Patterns (React / TypeScript)

## Icon-only button

```tsx
<button type="button" onClick={onDelete} aria-label="Supprimer l'élément">
  <TrashIcon aria-hidden="true" focusable="false" />
</button>
```

## Input with error

Label bound by `htmlFor`/`id`; hint and error linked through `aria-describedby`;
`aria-invalid`; the error is `role="alert"`. Full shape (with RHF): `forms.md`.

```tsx
<input
  id="email"
  name="email"
  type="email"
  autoComplete="email"
  aria-invalid={error ? "true" : "false"}
  aria-describedby={["email-hint", error ? "email-error" : null].filter(Boolean).join(" ")}
/>
```

The wrapper is a `<div>`, not a `<fieldset>`: one labelled field is not a group
(`templates/component.md`, "Why a `<div>` here").

## Modal (dialog natif)

Use the native `<dialog>`: `showModal()` gives the focus trap, inert background
and top layer. Sync `isOpen` to `showModal()` / `close()` in an effect, label it
with `aria-labelledby` on its `<h2>` (`useId`), and map the `cancel` event
(Escape) to `onClose` with `preventDefault()` so React state stays the source of
truth. Provide an icon-only close button with `aria-label="Fermer"`.

```tsx
useEffect(() => {
  const dialog = dialogRef.current;
  if (!dialog) return;
  if (isOpen && !dialog.open) dialog.showModal();
  if (!isOpen && dialog.open) dialog.close();
}, [isOpen]);

useEffect(() => {
  const dialog = dialogRef.current;
  if (!dialog) return;
  const handleCancel = (e: Event): void => {
    e.preventDefault();
    onClose();
  };
  dialog.addEventListener("cancel", handleCancel);
  return () => dialog.removeEventListener("cancel", handleCancel);
}, [onClose]);
```

## Skip link

```tsx
<a href="#main-content" className="sr-only focus:not-sr-only">
  Aller au contenu principal
</a>

<main id="main-content" tabIndex={-1}>{/* content */}</main>
```

`tabIndex={-1}` on `<main>` is what lets the skip link move focus into it. Use
Tailwind's native `sr-only`; do not redefine it.

## Dropdown menu (simple actions)

An ARIA `menu` is a **keyboard widget**, not just a list that appears. Three
things are non-negotiable, and the naive version gets all three wrong:

1. `role="menuitem"` goes on the **focusable** element — the `<button>`, never on
   the `<li>` wrapping it (the `<li>` takes `role="none"`). Otherwise the menu
   announces items that cannot be reached.
2. `Escape` closes and **returns focus to the trigger**, otherwise focus is lost
   at the top of the document.
3. `ArrowDown` / `ArrowUp` move between items (wrapping), `Home` / `End` jump to
   the ends — what distinguishes a `menu` from a plain list of buttons.

If you do not want to implement all three, **do not use `role="menu"`**: a plain
`<ul>` of `<button>`s is fully accessible and claims nothing it doesn't do.

Also: focus the first item on open (items `tabIndex={-1}`), close on outside
`pointerdown`, close and refocus the trigger after an item is chosen; the trigger
carries `aria-haspopup="menu"`, `aria-expanded`, and `aria-controls` while open.

```tsx
const onMenuKeyDown = (e: React.KeyboardEvent): void => {
  const last = items.length - 1;
  const current = itemRefs.current.findIndex((el) => el === document.activeElement);

  if (e.key === "Escape") {
    e.preventDefault();
    close(true); // setIsOpen(false) + triggerRef.current?.focus()
  } else if (e.key === "ArrowDown") {
    e.preventDefault();
    itemRefs.current[current >= last ? 0 : current + 1]?.focus();
  } else if (e.key === "ArrowUp") {
    e.preventDefault();
    itemRefs.current[current <= 0 ? last : current - 1]?.focus();
  } else if (e.key === "Home") {
    e.preventDefault();
    itemRefs.current[0]?.focus();
  } else if (e.key === "End") {
    e.preventDefault();
    itemRefs.current[last]?.focus();
  }
};

// <ul id={menuId} role="menu" onKeyDown={onMenuKeyDown}>
//   <li role="none"><button type="button" role="menuitem" tabIndex={-1} ref=… /></li>
```

## Live regions

```tsx
{/* Non-urgent: announced when the screen reader is idle */}
<div aria-live="polite" aria-atomic="true" className="sr-only">{notification}</div>

{/* Urgent: interrupts. `role="alert"` is an implicit aria-live="assertive" */}
{errorMessage && <div role="alert">{errorMessage}</div>}
```

> **The polite region is rendered unconditionally, empty.** A live region has to
> exist in the DOM *before* the text lands in it — mounting the element and its
> content at the same moment gives the screen reader nothing to observe, and the
> message is silently dropped. The urgent one can mount with its content because
> `role="alert"` is announced on insertion.

## Motion and reduced motion

Every animation respects `prefers-reduced-motion`: under `reduce`, no transform or
layout animation runs, and the page stays complete and readable. An animation
never carries a state change alone, the text or icon stays. Tools and examples:
`patterns/motion.md` (default) and `patterns/gsap.md` (only when a spec declares it).

## A11y tests (jest-axe + Vitest)

`pnpm add -D jest-axe @types/jest-axe` (compatible with Vitest).

```typescript
import { axe, toHaveNoViolations } from "jest-axe";
import { render } from "@testing-library/react";
import userEvent from "@testing-library/user-event";
import { expect, it } from "vitest";

expect.extend(toHaveNoViolations);

it("has no accessibility violations", async () => {
  const user = userEvent.setup();
  const { container } = render(<MyComponent />);
  await user.tab();

  expect(await axe(container)).toHaveNoViolations();
});
```
